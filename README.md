# 今日のボード

iPhone / iPad の Safari で使う、自分専用の1ページダッシュボードです。
訪問・受注ポイント・歩合・支出を1画面で記録・確認できます。
HTML + CSS + バニラJS で作っており、ビルドは不要です。ホーム画面に追加すると PWA として全画面で動きます。

## ファイル構成

```
index.html              画面の骨組み(3枚のカード)
manifest.webmanifest    PWA 設定
sw.js                   Service Worker(オフライン起動用のキャッシュ)
icons/                  ホーム画面アイコン
css/app.css             デザイントークンとレイアウト(390px 基準、768px 以上で2カラム)
js/
  main.js               起動処理
  config.js             ノルマ・歩合表・給料日・同期先などの設定値
  lib/date.js           日付計算(今週の月〜金、26日〜翌25日の期、暦月、給料日まで)
  lib/logic.js          集計・歩合判定・表示用の整形
  lib/charts.js         SVG グラフと表
  store/store.js        アプリの状態(画面はここだけを読み書き)
  store/local.js        localStorage への保存
  sync/engine.js        同期の進行役(未送信キュー、再試行、状態表示)
  sync/none.js          同期なし
  sync/supabase.js      Supabase 同期(REST API を fetch で呼ぶ)
  ui/*.js               ヘッダー・訪問・受注・お金・同期シート
supabase/schema.sql     Supabase のテーブル定義
tests/logic.test.js     日付計算と歩合のテスト
```

### データの持ち方

すべての記録を、種類を問わず同じ形 `{ kind, id, data, updatedAt, deleted }` で持ちます。

| kind | id | data |
|---|---|---|
| `visit` | 日付 `YYYY-MM-DD`(1日1件) | `{ date, effective, cold }` |
| `order` | ランダムな ID | `{ date, points, note }` |
| `expense` | ランダムな ID | `{ date, amount, cat, note }` |
| `goal` | 月 `YYYY-MM` | `{ month, points }` |

- 削除しても記録は消さず、`deleted: true` の印を付けます。そのまま他の端末へも同期されます。
- 同じ記録を複数の端末で書き換えた場合は、`updatedAt` が新しい方を採用します(後勝ち)。
- **カレンダー連携を後から足すとき**は、`kind: 'calendar'` のような種類を1つ増やし、`ui/` に表示部品を1つ足して `main.js` の `views` に加えるだけで済みます。保存・同期・テーブルの変更は不要です。

## ステップ2:ローカル保存版の動作確認

### パソコンで確認する

```sh
python3 -m http.server 8080      # または npm start
# ブラウザで http://localhost:8080 を開く
npm test                         # 日付計算と歩合のテスト(Node.js 18 以上)
```

### 確認手順

1. **空の状態**:初めて開いたときに `NaN` や `undefined` が出ておらず、どの数字も 0 または ¥0 になっていること。
2. **ヘッダー**:英語の日付(例 `Mon, Oct 26, 2026`)が出ること。「給料日まで N 日」が正しいこと(10/26 なら 30 日、25日当日は「今日は給料日」)。右下の同期表示が「端末に保存」になっていること。
3. **訪問**
   - 有効訪問の「+1」を2回押すと、タイルの枠と数字が緑になり「✓ 達成」と表示されること。
   - 「取消」で1件減ること。0件のときは取消ボタンを押せないこと。
   - 今週のグラフで、今日の曜日に背景が付いて強調されていること。凡例の「計N」が週の合計と一致すること。
   - 棒をタップすると、下に「10/26(月) 有効 2件・飛込 1件」のように表示されること。
   - 「表」を押すと同じ内容が表で表示され、「グラフ」で元に戻ること。
4. **受注ポイント**
   - ポイント 120 を追加すると、合計・達成率・バーが変わること。歩合の目安は ¥0 のまま、「次の段階まで あと 30 pt / 150P 到達で ¥10,000」と表示されること。
   - 合計が 150 以上になると「歩合の目安 ¥10,000」に変わること。「歩合表を見る」を開くと、該当する行が緑色で「現在」と表示されること。
   - 一覧の「削除」を1回押すと「もう一度で削除」に変わり、もう一度押すと消えること。3秒放置すると元に戻ること。
   - 月目標に 250 を入れて保存すると、「/ 250 pt」に変わること。
   - 先月の日付で追加すると、「今月の合計には入りません」と表示されること。
5. **お金**
   - タイトルが「支出 10.26 – 11.25」(今期)になっていること。
   - 金額とカテゴリを選んで追加すると、合計・積み上げバー・カテゴリ別の金額と割合が変わること。
   - 金額に `abc` や `0` を入れると、エラーメッセージが出て追加されないこと。`1,200` や全角の `１２００` は受け付けること。
   - 推移グラフの棒をタップすると、その期だけ色分けされ、下にカテゴリ別の内訳が出ること。もう一度タップすると閉じること。
6. **保存**:再読み込みしても記録が残っていること。
7. **レイアウト**:幅 390px では1列、iPad(幅 768px 以上)では左に訪問と受注、右にお金の2列になること。どちらの幅でも横スクロールが出ないこと。
8. **オフライン**:一度開いたあと、開発者ツールでオフラインにして再読み込みしても起動し、記録できること。

### iPhone で確認する

GitHub Pages などで HTTPS 公開したページを Safari で開き、共有ボタンから「ホーム画面に追加」を選びます。追加したアイコンから起動すると、アドレスバーのない全画面で表示されます。

> **GitHub Pages の公開方法**:リポジトリの Settings → Pages → Build and deployment で Source を「Deploy from a branch」にし、公開したいブランチとフォルダ `/ (root)` を選んで Save します。数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で開けます。
> 無料プランでは、GitHub Pages は公開リポジトリでしか使えません。Supabase の anon キー(publishable キー)は公開しても問題ない値で、データはログインと RLS で守られます。

## claude.ai のページとして使う(Supabase 不要)

claude.ai 上の非公開ページとして公開すると、そのページのデータ保存機能で iPhone と iPad の記録がそろいます。この場合 Supabase の設定はいりません。

- 1ファイル版を作る:`npm install` のあと `npm run build:artifact`(`dist/today-board.html` ができる)
- 同期先:閲覧している本人だけが読み書きできる領域(`data/users/<本人のID>/`)に、「種類 × 月」ごとにまとめて保存します。
- 制限:オフライン起動はできません。ホーム画面から開くと Safari の画面になります(全画面表示にはなりません)。

## ステップ3:同期の設定(Supabase)

### Supabase を選んだ理由

- **依存が増えない**:REST API なので `fetch` だけで書け、SDK もビルドもいりません。Firebase はブラウザで使うには大きな SDK が事実上必要です。
- **ローカル優先の作りと相性がよい**:オフライン対応は自前の未送信キューで行うので、Firebase の SDK に組み込まれたオフライン機能は必要ありません。
- **アクセス制限がわかりやすい**:RLS(行単位のアクセス制限)を SQL で数行書くだけで「自分の行だけ」にできます。
- **無料枠で十分**:データベース 500MB に対し、このアプリの記録は年間でも数 MB です。
- **注意点**:無料プランでは、**7日間アクセスがないとプロジェクトが一時停止**します。毎日使っていれば止まりません。止まった場合は、Supabase の管理画面で Restore を押すと再開できます。停止中もアプリは端末内に記録を続け、再開後に同期されます。

### 設定手順

1. **プロジェクトを作る**
   [supabase.com](https://supabase.com) でサインアップし、「New project」を押します。名前とデータベースのパスワードを決め、リージョンは `Northeast Asia (Tokyo)` を選びます。
2. **テーブルを作る**
   左メニューの **SQL Editor** を開き、このリポジトリの `supabase/schema.sql` の中身を全部貼り付けて **Run** を押します。「Success」と出れば完了です。
3. **自分のユーザーを作る**
   **Authentication → Users → Add user → Create new user** を開き、メールアドレスとパスワードを入れます。「Auto Confirm User」にチェックを入れて作成します。
4. **他人が登録できないようにする**
   **Authentication → Sign In / Providers**(画面によっては Providers → Email)を開き、**Allow new users to sign up** をオフにして保存します。
5. **URL とキーを控える**
   **Project Settings → API**(または画面上部の Connect)を開き、次の2つを控えます。
   - Project URL(`https://xxxx.supabase.co`)
   - `anon` `public` キー。新しい画面では `sb_publishable_...` で始まる Publishable key です。
   **`service_role` / secret キーは絶対に使わないでください。**
6. **アプリに設定する**
   `js/config.js` の `SYNC` に書き込み、コミット・公開します。
   ```js
   export const SYNC = {
     supabaseUrl: 'https://xxxx.supabase.co',
     supabaseKey: 'eyJhbGciOi...(anon キー)',
   };
   ```
7. **ログインする**
   アプリ右上の同期表示(「未ログイン」)をタップし、手順3のメールアドレスとパスワードでログインします。それまで端末に保存していた記録は、ログイン時にまとめて送られます。

### 同期のしくみ

- 記録はまず端末に保存して、すぐ画面に反映します。同時に未送信キューへ積み、約0.6秒後に裏で送ります。
- 同期するタイミングは、起動時、記録の直後、オンラインに戻ったとき、アプリが前面に戻ったとき、5分ごとです。
- 送信では、未送信キューの記録をまとめて upsert します。受信では、前回以降にサーバーに届いた記録(`server_at`)だけを取得します。
- サーバー側にもトリガーを置き、古い記録で新しい記録を上書きしないようにしています(後勝ち)。
- 同期表示の意味は次のとおりです。

| 表示 | 意味 |
|---|---|
| 端末に保存 | 同期は未設定(端末内のみ) |
| 保存中… | 送受信中 |
| 保存済み | サーバーと同じ状態 |
| オフライン · 未送信 N | 通信できない。戻れば自動で送る |
| 未ログイン | ログインが必要(タップでログイン) |
| 同期エラー | サーバーがエラーを返した(タップで詳細) |

- 既知の制限:2台の端末が**両方オフラインのまま**同じ日に訪問の「+1」をすると、その日の訪問件数は後から同期した方の値になります(1日1レコードの後勝ちのため)。

### ステップ3の動作確認

1. 設定後にアプリを開くと、右上が「未ログイン」になっていること。タップしてログインすると「保存済み」に変わること。
2. わざと違うパスワードを入れると、「メールアドレスかパスワードが違います」と出ること。
3. iPhone で訪問「+1」と支出を1件記録し、表示が「保存中…」→「保存済み」と変わること。
4. iPad でログインし(または開き直し)、同じ件数と支出が表示されること。
5. iPhone を機内モードにして記録すると「オフライン · 未送信 1」になること。機内モードを解除すると、自動で「保存済み」に戻ること。iPad を開き直すと、その記録が反映されていること。
6. iPad で支出を削除すると、iPhone を開き直したときに消えていること。
7. Supabase の **Table Editor → records** で、記録が行として入っていることを確認できます。

## 設定値を変えたいとき

`js/config.js` で変更できます。

- `QUOTA`:日次ノルマ
- `PAYDAY`:給料日(支出の期は翌日から)
- `DEFAULT_MONTHLY_GOAL`:月目標が未設定のときの値
- `COMMISSION_TIERS`:歩合表
- `CATEGORIES`:支出カテゴリと色

公開後に変更した場合は、`sw.js` の `VERSION` を上げると、端末のキャッシュが確実に新しいものへ入れ替わります。
